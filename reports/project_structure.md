# SentinelAI — Project Structure

Purpose of the important directories (generated/temporary files
omitted; `.gitkeep` markers and caches are not listed).

## `src/` — application source

| Subpackage | Purpose | Key entry points |
| --- | --- | --- |
| `src/data/` | Dataset loading + inspection tooling (Part 3) | `python -m src.data.inspect_dataset` |
| `src/preprocessing/` | Cleaning, encoding, leakage-safe split, artifacts, reports (Part 4) | `python -m src.preprocessing.pipeline` |
| `src/training/` | Baseline training (Part 5), tuning/comparison (Part 6), artifact save/load | `python -m src.training.train_binary`, `python -m src.training.model_comparison` |
| `src/evaluation/` | Test-set metrics, classification reports, figures (Part 5) | `python -m src.evaluation.evaluate_binary` |
| `src/detection/` | Threat detection engine: validation, transform-only preprocessing, prediction, structured results (Part 7) | `python -m src.detection.detector` |
| `src/response/` | Controlled response: policy, actions/statuses, engine, detect→respond→store CLI (Part 7) | `python -m src.response.response_engine` |
| `src/network/` | Offline PCAP analysis: safe reader, flow reconstruction, feature subset, compatibility gate (Part 10) | `python -m src.network.pcap_pipeline` |
| `src/utils/` | Shared utilities (logging foundation) | — |
| `main.py` | Environment banner / entry point | `python main.py` |

## `database/` — persistence layer

`schema.sql` (tables + indexes), `connection.py` (context manager +
idempotent additive migration), `repository.py` (the only DB interface:
parameterized queries, integrity validation, statistics),
`models.py` (record types + detection/response mapping).
Runtime file `sentinelai.db` is **git-ignored**.

## `dashboard/` — Streamlit UI

`app.py` (thin shell + navigation), `pages.py` (five page functions),
`services/dashboard_service.py` (data layer; no SQL, no Streamlit
import), `components/` (metric cards, matplotlib charts, table).

## `models/` — trained artifacts (git-ignored binaries)

`xgboost_optimized.joblib` (+ `metadata/`), the other optimized and
baseline models, and `preprocessing/` (preprocessor, label encoder,
feature-column metadata). Excluded from Git by the project's
established policy — they are regenerated by the documented pipeline.

## `config/` — configuration

`settings.py` (project identity, base paths), `model_config.py`
(seed 42, CV, search spaces, documented reductions),
`detection_config.py` (active model file, severity thresholds). No
secrets — a `.env.example` template exists at the root.

## `data/` — datasets

`raw/` (official CIC-IDS2017 CSVs — git-ignored), `processed/`
(train/test CSVs + figures inputs — git-ignored), `sample/`
(small reproducible development sample, trackable).

## `reports/` — documentation & results

Phase reports (`part4…part11`), design documents
(`detection_engine.md`, `database_design.md`, `dashboard_design.md`,
`pcap_analysis.md`, and the Part 12 final documents), audits
(leakage, reproducibility, coverage, security), dataset documentation,
model-results tables, generated figures (`figures/`) and CV results
(`cv_results/`).

## `tests/` — automated validation

- Top level: unit suites per component.
- `integration/`: full offline pipelines (CSV chain; PCAP full chain
  through a temporary database to the dashboard service).
- `validation/`: programmatic security/portability scans, response
  safety, PCAP safety.

## Root files

`requirements.txt` (pinned-need list), `README.md` (full project doc),
`DEVELOPMENT.md` (beginner quick-start + per-part commands),
`CONTRIBUTING.md` (defensive-only contribution policy),
`.gitignore` (datasets, database, venv, logs, secrets, models, caches),
`.env.example` (credential-free template), `pyproject.toml`
(pytest config + markers), `conftest.py` (shared fixtures).
